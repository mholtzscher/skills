# Prototype and visual parity

Distinguish a disposable decision experiment from a production change.

For a prototype, define the uncertainty, observable comparison, smallest sketch, output location, and disposal/preservation plan. Get sketch approval before writing code. Build only enough to answer the question. Compare actual results, state what was simulated, and recommend the next decision. A prototype does not automatically publish a PR or authorize production implementation.

For visual parity, establish the reference screenshot/implementation, viewport, data, interaction state, and allowed differences. Propose and approve the implementation shape. Capture comparable real screenshots and exercise interactions; an attractive mock is not parity evidence. Use the available browser or terminal specialist for the actual surface. Iterate on measured differences, preserve behavior, and use [finish delivery](finish-delivery.md) for an approved production change.
