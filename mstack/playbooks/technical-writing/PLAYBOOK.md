# Technical writing

1. Establish the audience, reader's goal, source material, and requested scope: draft, edit, or review. Read the complete selected text and applicable repository writing conventions.
2. Read the [technical-writing standard](../../references/technical-writing.md). For documentation, choose the Diátaxis mode before drafting. Preserve required RFC, planning, README, and PR templates; use distinct sections or linked pages where their purposes differ.
3. Draft or review against all applicable layers. Check real symbols, paths, flags, commands, output, counts, and behavior claims against the source. Distinguish proposed behavior from implemented behavior. Report unavailable evidence rather than inventing it. Include regeneration commands for counts and trees.
4. Run [Prose cleanup](../cleanup/PLAYBOOK.md#prose-cleanup) on the selected text. Review-only requests produce findings and suggested wording without edits. Apply requested edits within scope; changes to technical requirements need agreement.

Finish with the requested artifact or review findings, material ambiguities, and any unverified claims. Writing or reviewing text does not authorize publication or implementation of the design it describes.
