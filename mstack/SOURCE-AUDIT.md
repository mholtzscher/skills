# Integrated-source audit

Audited 2026-10-15 against mstack `fbc0587` plus the spec-planner restoration in this change. This is a maintenance report, not agent-facing workflow instructions. The request was to extend the show-me/spec-planner fidelity audit to every integrated skill.

## Result

**The initial integration preserved broad intent much better than substantive source detail.** Consolidation preserved the already-condensed mstack text; it did not recover the instructions, examples, and references omitted earlier.

- **Restored:** show-me's complete body and ten examples; spec-planner's complete workflow and four references, with the adaptations recorded below.
- **Strong substantive coverage:** verification-skill Create/Maintain and all three feature-map examples; deslop's core checks; the principal workflow-tools PR/spec contracts. These are adaptations, not verbatim copies.
- **Substantial remaining losses:** show-complexity, domain-modeling's formats, architect/arena/swarm, how/why, review/blast-radius, benchmarking/hillclimbing, reflection, and decision trails.
- **Smaller but real losses:** grilling's completion/round contract, the orchestrator's detailed dispatch examples and role constraints, teaching/catch-up output guidance, and several testing/forensics/refactoring details.
- **Policy differences requiring care:** approval, selective delegation, host-owned models, one ordinary unmerged PR, comment preservation, and separate installation are accepted mstack choices. Their existence does not establish approval for every other omitted clause.

Only the previously approved spec-planner restoration is implemented by this follow-up. The other findings are an audit and proposed restoration order, not newly accepted workflow policy.

## Evidence and method

Compared instruction bodies, examples, resource inventories, routing, and permission/stopping conditions. Checked destinations across the bundle, including shared rules, principles, host adapters, and references, rather than treating a missing sentence in one playbook as necessarily missing everywhere. Line counts below locate the scale of condensation; they are not fidelity scores.

Sources:

1. **Pstack:** all 52 skill entry points inventoried, including 24 principle skills; all 23 `poteto-mode/playbooks/` entries mapped below. Comparison uses the [workflow-tools bundled snapshot](https://github.com/mholtzscher/opencode-plugins/tree/3f83b1d5b6b7e82adf7639148403083b4ccb4a8d/workflow-tools/pstack/upstream), which identifies pstack 0.15.21 at `1dcc2bac`. The bundled files include host adaptations, so they are not asserted byte-identical to raw Cursor upstream. The inspected source directories have no diff from workflow-tools `3f83b1d`.
2. **Local skills:** [spec-planner](https://github.com/mholtzscher/skills/tree/57f95bb94e4abaf6206f97188497958a7e81a1bc/spec-planner), [show-complexity](https://github.com/mholtzscher/skills/tree/57f95bb94e4abaf6206f97188497958a7e81a1bc/show-complexity), and the pre-deprecation `agent-orchestrator/SKILL.md` at that repository revision. The archived orchestrator adds a deprecation notice and invocation metadata; the baseline is the source for this comparison.
3. **Installed sources:** show-me, grilling, and domain-modeling from the installed copies identified in [provenance](PROVENANCE.md). Show-me is also pinned upstream at `bba9d13`. Grilling and domain-modeling have installer hashes, not verified upstream Git revisions; this audit claims fidelity against those installed copies.
4. **Deslop:** `pstack/team-kit/skills/deslop/SKILL.md` in workflow-tools `3f83b1d`, carrying the upstream revision recorded in provenance.
5. **Workflow-tools:** `specs/prompts.ts`, `pr/*-prompts.ts`, and the bundled helper interfaces. This is an instruction/coverage audit, not a fresh correctness audit of the original plugin or mstack's helper implementation.

**Status vocabulary:** “Retained” means the central procedure is present, with noted adaptations; “Partial” identifies substantive losses; “Restored” means the source body/resources were recovered with enumerated changes; “Absent” means no equivalent procedure was found. An absence is not automatically a commitment to add it. External skills remain external under [D10](DECISIONS.md#d10-vendor-selected-procedures-keep-specialists-external).

### Spec-planner restoration adaptations

- Replace independent skill discovery with the existing `planning.md#full-spec` section; adjust heading levels and relative links. Keep Sketch, Approval, and existing-spec Refine as separately routed sections.
- Apply phase reporting and the full interview only to the full-spec route. Count prior clarification/grilling answers toward its required exchange; avoid restarting a settled interview.
- Preserve the structured question example, question counts, discovery table, implementation contract, all completeness rows, estimates, scope-control examples, and final output. Translate unconditional OpenCode tools to the selected host's actual question/file/search/delegation tools, with conversational question fallback.
- Preserve authoritative research and bounded delegated discovery while referring to mstack's host/orchestration contracts rather than universal OpenCode call syntax.
- Write a reviewable draft before seeking approval; finalize it after approval. Honor an explicit output path, including nested/outside-`specs/` paths. Record actual approval state and stop before implementation unless the ongoing coding task already supplies that authority.
- Keep unresolved implementation-contract choices blocking. Assigned final open items must be non-blocking. Preserve estimates as estimates, with the source estimation reference.
- Restore `templates.md`, `decision-frameworks.md`, `estimation.md`, and `technical-debt.md` in full. Their only changes are Markdown formatting. Retire the condensed `spec-format.md` and `decisions.md` after checking their callers; preserve the separate domain-record resource.
- Keep attribution in maintenance/license files. The source's richer planning ADR template does not replace domain-modeling's lightweight ADR convention.

## Recommended restoration order

1. **Finish selected vendor fidelity:** show-complexity, grilling, and domain-modeling with both full format files; then the orchestrator's useful role/brief/acceptance details. Preserve host questions, approval, and selective delegation.
2. **Recover evidence quality:** why/how references, interrogate rubric/lead judgment, blast-radius proof ladder, benchmark checklist, hillclimb harness discipline, refactoring pins, and visual-parity baseline protections. Also correct the PR incomplete-review stopping gap through an approved focused change.
3. **Recover teaching and learning procedures:** teach/catch-up/recall examples, unslop pattern catalog, reflection references, and the decision-trail format/helper. Make model-specific and automatic external-write behavior explicit choices.
4. **Review principle losses individually:** recover concrete diagnostics and examples without reintroducing blanket branding, mandatory tool artifacts, automatic design panels, or no-approval execution by implication.
5. **Decide advanced scope separately:** full Autopilot/Orchestrate, worktree cleanup, personal-mode automation, bot UI, and missing technical specialists are capability additions or policy choices, not mechanical fidelity fixes.
